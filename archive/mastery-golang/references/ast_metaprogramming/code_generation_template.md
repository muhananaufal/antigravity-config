# Code Generation di Go: Template, Jennifer, dan Format

> **Berlaku:** Go 1.21+ · `text/template` · `go:generate` · **Lihat juga:** `ast_metaprogramming/go_ast_analysis.md` · `ast_metaprogramming/protoc_plugin_generator.md` · `db_sqlc/sqlc_pgx_driver.md` · `microservices_grpc/openapi_ogen_codegen.md`

## Konsep Utama dan Internal

Fitur `//go:generate` di Go merupakan fasilitas *first-class* untuk eksekusi skrip atau *tooling* saat pra-kompilasi. Dalam skenario pengembangan modern, seringkali *boilerplate code* yang masif (enumerator, *mocking*, model API, adapter GORM) ditulis secara manual, padahal sumber kebenarannya bisa ditarik dari anotasi kustom, JSON Schema, atau definisi Database. 

Di ekosistem Go, melakukan kode sintesis atau code generation dapat dipecahkan melalui 2 teknik utama:
1. **`text/template` dengan format.Source**: Pendekatan klasik di mana string *template* diinjeksi dengan struct data. Kekurangannya, template rentan rusak akibat masalah spasi, koma yang terlewat, dan kurangnya inspeksi *syntax checking* saat penulisan.
2. **`dave/jennifer` (DSL Go AST Builder)**: Solusi mutakhir standar industri. Jennifer menyediakan antarmuka *builder pattern* (*type-safe*). Daripada merangkai string, Anda membangun struktur Abstract Syntax Tree (AST) secara programatik (misal `jen.Func().Id("Run").Block()`). Keunggulannya: kompilator memastikan Go syntax tak akan patah, dan secara implisit me-run standar `gofmt` ke blok memori buffer.

## Kode Go Production-Ready

Kode di bawah ini mendemonstrasikan alat *generator* produksi (menggunakan `dave/jennifer`) yang me-render status tipe kustom enumerator (`Enum`) beserta fungsi helper (`String()` dan `IsValid()`) ber-basis data input murni.

```go
package codegen

import (
	"bytes"
	"fmt"
	"os"
	"testing"

	"github.com/dave/jennifer/jen"
)

// =====================================
// 1. INPUT DEFINITION
// =====================================

// EnumDef merepresentasikan input data/schema abstrak yang akan di-render menjadi source Go.
type EnumDef struct {
	TypeName string
	Values   []string
}

// =====================================
// 2. CODE GENERATOR LOGIC (dave/jennifer)
// =====================================

// GenerateEnum memanfaatkan Jennifer DSL untuk men-generate file Enum secara Type-Safe
func GenerateEnum(pkgName string, def EnumDef) ([]byte, error) {
	if len(def.Values) == 0 {
		return nil, fmt.Errorf("no values provided for enum type: %s", def.TypeName)
	}

	// Inisiasi sebuah file AST / Builder baru di package tertentu.
	f := jen.NewFile(pkgName)
	
	// HEADER CRUCIAL: Mencegah developer (dan Linter) untuk memodifikasi.
	f.HeaderComment("Code generated by enumgen-tool. DO NOT EDIT.")

	// Blok 1: type Role string (Definisi Custom Type)
	f.Type().Id(def.TypeName).String()

	// Blok 2: constanta enumerator
	// const (
	//     RoleAdmin Role = "Admin"
	// )
	f.Const().DefsFunc(func(g *jen.Group) {
		for _, val := range def.Values {
			g.Id(def.TypeName + val).Id(def.TypeName).Op("=").Lit(val)
		}
	})

	// Blok 3: func (e Role) String() string
	f.Func().
		Params(jen.Id("e").Id(def.TypeName)). // Receiver func
		Id("String").                         // Func Name
		Params().                             // Kosong (Tidak ada parameter input)
		String().                             // Return string
		Block(
			jen.Return(jen.String().Call(jen.Id("e"))), // Body return string(e)
		)

	// Blok 4: Validasi helper: func (e Role) IsValid() bool
	// Ini melindungi Domain kita dari enum abal-abal yang di-cast sembarangan.
	f.Func().
		Params(jen.Id("e").Id(def.TypeName)).
		Id("IsValid").
		Params().
		Bool().
		Block(
			jen.Switch(jen.Id("e")).BlockFunc(func(g *jen.Group) {
				// Iterasi untuk semua valid values
				for _, val := range def.Values {
					g.Case(jen.Id(def.TypeName + val)).Block(jen.Return(jen.True()))
				}
				g.Default().Block(jen.Return(jen.False()))
			}),
		)

	var buf bytes.Buffer
	// Proses Render akan otomatis memancarkan source code valid dan mem-formattingnya (gofmt)
	if err := f.Render(&buf); err != nil {
		return nil, fmt.Errorf("failed to render generated ast to code: %w", err)
	}

	return buf.Bytes(), nil
}

// WriteToFile adalah helper akhir dari eksekusi eksternal
func WriteToFile(filename string, data []byte) error {
	return os.WriteFile(filename, data, 0644)
}

// =====================================
// 3. UNIT TEST
// =====================================

func TestGenerateEnum_ProducesValidGoCode(t *testing.T) {
	def := EnumDef{
		TypeName: "Role",
		Values:   []string{"Admin", "User", "Guest"},
	}

	out, err := GenerateEnum("models", def)
	if err != nil {
		t.Fatalf("Unexpected error generating enum: %v", err)
	}

	strOut := string(out)

	// Validasi struktur dan sintaks krusial di file target
	expectedKeywords := []string{
		"package models",
		"// Code generated by enumgen-tool. DO NOT EDIT.",
		"type Role string",
		"RoleAdmin Role = \"Admin\"",
		"func (e Role) String() string",
		"func (e Role) IsValid() bool",
		"case RoleGuest:",
	}

	for _, expected := range expectedKeywords {
		if !bytes.Contains(out, []byte(expected)) {
			t.Errorf("Generated code missing strictly required line: %s\nActual Result:\n%s", expected, strOut)
		}
	}
}
```

## Anti-Patterns

### ❌ Anti-Pattern 1: Pemasangan Template Mentah (Raw String) Tanpa `gofmt`
Ini adalah praktik kuno yang sangat sering dijumpai pada tools in-house. Pengembang menggunakan `text/template` dan tidak merapihkan indentasi maupun package imports saat render di-dump ke dalam `.go`.

```go
// ❌ BAD: Format spasi bisa bergeser dan merusak build CI/CD linter
const tmpl = `package {{.Pkg}}
type {{.Name}} struct{}` // Spasi struct kacau!

func Generate() {
    t := template.Must(template.New("").Parse(tmpl))
    t.Execute(os.Stdout, data) // Dikeluarkan begitu saja.
}
```
**Why dangerous:** File output (`.go`) hasil generate tersebut mungkin memiliki tab atau spasi tidak baku. Ketika developer lain menarik (pull) dan menyentuh folder tersebut dengan IDE (goland/vscode), IDE otomatis menjalankan *format-on-save* dan mengubah *diff git* secara tidak perlu yang memperkotor sejarah *Commit/PR*.
**Solusi (Benar):** Selalu bungkus hasil render buffer `text/template` dengan `golang.org/x/tools/imports.Process("file.go", buf.Bytes(), nil)` yang akan mengurutkan *imports* (menghapus yang tak terpakai) dan menerapkan spesifikasi standar `gofmt`. (Catatan: Tool `jennifer` sudah mengatasi ini secara internal *out-of-the-box*).

### ❌ Anti-Pattern 2: Melupakan Proteksi Header "DO NOT EDIT"
Pengembang lupa meletakkan komentar ajaib (directive standar Go) di file hasil *generate*.

```go
// ❌ BAD: Output file .go tidak melampirkan label autogenerated.
```
**Why dangerous:** Jika tidak ada indikasi standar, Junior Developer yang tidak tahu asal-usul *file* tersebut akan memodifikasi logika fungsi di dalam file hasil generate tersebut secara manual demi mempercepat bug-fixing. Keesokan harinya saat pipeline CI memanggil perintah `go generate ./...`, semua kerja keras perbaikan manual *hilang/terhapus tanpa sisa* karena file tersebut ditiban oleh mesin (overwritten). Linter (seperti `golangci-lint`) juga akan membuang waktu me-lint file *generated* jika header peringatannya luput dipasang.
**Solusi (Benar):** Pada baris Paling Atas di file, sebelum mendeklarasikan package, tulis secara persis: `// Code generated by <nama-tool>. DO NOT EDIT.` 

## Edge Cases & Defensive Programming Konkrit

1. **Unsafe String Identifiers dari Skema Pihak Ketiga (JSON/YAML):**
   Bayangkan jika definisi sumber berasal dari file JSON pelanggan eksternal di mana suatu kolom bernama `1st Place` (berawalan angka, ilegal di Go) atau `Name-Here` (karakter spasi/strip yang tidak ter-parse oleh operator bahasa). Jika ini langsung dimasukkan ke `jen.Id("1st Place")`, kompilasi kode hasil `generate` akan pecah (Syntax error).
   *Defensive:* Tulis layer *Sanitizer/Normalizer* (RegEx filter/Capitalize) murni yang menghapus atau mereplace karakter *Non-Alphanumeric* dan memastikan karakter pertama bukanlah digit. Gunakan library konversi *TitleCase* yang mumpuni sebelum string masuk ke engine Jennifer.

2. **Empty Generation Slices Memecah Syntax Strict (Unused Vars / Fall-through Blocks):**
   Input data schema tanpa entri (Slice `len == 0`) saat diproses dengan loop di block `jennifer` mungkin saja memicu pembuatan blok *switch-case* atau variabel yang tak bernilai. Meskipun secara tata bahasa berhasil dikompilasi, *Go Compiler* sangat ketat (strict) menanggapi *unused variables/imports*.
   *Defensive:* Lakukan validasi pra-syarat eksekusi mutlak sebelum memulai memori builder (`if len(values) == 0 { return fmt.Errorf(...) }`).

3. **Build Tag Isolation (Pemblokiran Karantina Tool Code Generator):**
   Kode `.go` dari alat (tooling program `main` generatornya sendiri) seringkali tertumpuk berdampingan dengan hirarki folder kode bisnis (API) yang dihasilkan. Ketika aplikasi utama (Main App API) di-build, *compiler Go* mencoba mengikutsertakan source tools generator tersebut yang bisa mengakibatkan *panic duplicate "main" func* atau dependensi impor `dave/jennifer` merembes ke binari produksi.
   *Defensive:* Tambahkan perlindungan Build Constraints (Tags) di baris absolut atas pada file sumber generatornya (`//go:build ignore` atau `//go:build !generate`). Opsi lain adalah memisahkannya ke folder khusus `tools/` atau `cmd/generator/` yang di-trigger dari root menggunakan argument absolut (misal `go run ./tools/generator.go -type=Status`).

## Kapan JANGAN Pakai Ini

- **Untuk sesuatu yang bisa diselesaikan generik.** Sejak Go 1.18, banyak kode yang dulu di-generate cukup ditulis sekali dengan parameter tipe — tanpa langkah build, tanpa berkas yang harus disinkronkan.
- **Kode generate yang disunting manual.** Suntingan akan hilang pada regenerasi berikutnya, dan orang yang menyuntingnya tidak akan tahu sampai perubahannya diam-diam menghilang.
- **Tanpa gerbang CI yang memastikan hasil generate sinkron.** Kode generate yang basi adalah kebohongan yang dikompilasi dengan sukses. `go generate ./... && git diff --exit-code`.
- **Tanpa penanda "jangan disunting" di berkas hasil.** Konvensi `// Code generated ... DO NOT EDIT.` dikenali alat dan pembaca; menghilangkannya mengundang suntingan manual.
- **Generator yang menghasilkan kode tak terbaca.** Kode generate tetap dibaca manusia saat men-debug produksi. Formatnya harus melewati `gofmt` dan tetap masuk akal.

## Cara Mendeteksi Gejalanya di Produksi

| Gejala | Yang dilihat | Artinya |
| :--- | :--- | :--- |
| Perilaku tidak sesuai definisi sumber | hasil `go generate` + `git diff` | Kode generate basi |
| Perubahan hilang setelah regenerasi | penanda DO NOT EDIT | Berkas hasil disunting manual |
| Sulit men-debug kode generate | keterbacaan keluaran | Generator menghasilkan kode yang tidak bisa dibaca |
| Build gagal di mesin lain | dependensi generator | Generator tidak tercatat di `tools.go` |
| Banyak kode generate yang mirip | apakah generik bisa dipakai | Generasi kode untuk masalah yang sudah punya solusi bahasa |

```bash
# Gerbang paling penting: hasil generate WAJIB sinkron dengan sumbernya
go generate ./... && git diff --exit-code

# Berkas hasil generate yang tidak punya penanda
grep -rLn 'Code generated' --include='*_gen.go' --include='*.pb.go' . | head

# Versi generator harus tercatat agar hasilnya reproducible
cat tools.go 2>/dev/null
go list -m all | grep -iE 'protoc|sqlc|mockgen|stringer'
```
