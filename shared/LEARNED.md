## 🌿 Git Flow, Branching & PowerShell Windows

- `-ne` untuk string bersifat **case-insensitive** → `"Wajib" -ne "WAJIB"` bernilai `$false`. Pakai `-cne`.
- `Write-Output` di dalam fungsi **mencemari nilai balik**; string informasinya dikira data. Pakai `Write-Host`.
- Melempar **string kosong** ke parameter membuat PowerShell membuang argumennya → error "Missing an argument".
- Berkas `.ps1` WAJIB **ASCII murni**. PowerShell 5.1 salah membaca UTF-8 tanpa BOM pada skrip.
- Berkas `.md` WAJIB **UTF-8 tanpa BOM**. `Set-Content`/`Out-File` bawaan merusaknya; pakai `[IO.File]::WriteAllText` + `UTF8Encoding($false)`.
- **Kutip ganda di pesan `git commit -m`** dipecah jadi argumen terpisah. Pakai `git commit -F <berkas>`.
- Glob `*_protocol*` ikut mencocoki `networking_protocols_grpc`. Periksa hasil filter path sebelum menulis massal.
- **Operator `&&` tidak valid** di PowerShell 5.1 → error "The token '&&' is not a valid statement separator". Pakai `;` atau jalankan perintah secara terpisah.
- **Setiap Git commit WAJIB menyertakan Co-author trailer:** `Co-authored-by: aetheris <agents.aetheris@gmail.com>`. DILARANG menggunakan `Antigravity <antigravity@google.com>` karena di-link GitHub secara otomatis ke akun publik pengguna lain (`shimonenator`). Setiap branch feature fase WAJIB di-merge ke `main` terlebih dahulu sebelum di-push ke remote.
- **Trailer `aetheris` WAJIB di SEMUA platform, termasuk Claude Code.** `meta-git` catatan platform sempat memerintahkan menggantinya dengan `Co-authored-by: Claude` khusus di Claude Code — bertabrakan dengan Gerbang Mutlak §0.6, sementara `tool-claude-code.md` CC-3 mengklaim "sesuai meta-git" padahal isinya berbeda. Diperbaiki 2026-08-28 (menambah, bukan mengganti). **Aturan yang saling merujuk WAJIB dibaca dua arah: klaim "sesuai X" bukan bukti bahwa X mengatakan hal yang sama.**

## 🧪 Verifikasi Alat CLI & Code Generator

- **Test hijau membuktikan berkas ditulis, bukan berkas itu kompilasi.** Di generator kode, satu-satunya gerbang yang bermakna adalah menjalankan toolchain asli pada outputnya (`go build` + `go vet` + `gofmt -l` di `t.TempDir()`). Tanpa itu, `go-aether` merilis `init` yang outputnya gagal `go build` di perintah pertama pengguna, dan 5 command per-layer yang templatnya sudah menyimpang — semua dengan suite 100% hijau.
- **Menjalankan biner menemukan apa yang test tidak bisa.** Tiga defek nyata hanya muncul saat eksekusi: `go.mod` ber-BOM dilaporkan "bukan modul Go", `arch:domain con` sukses palsu (Win32 device), dan auditor baru menuduh kode yang alatnya sendiri hasilkan. Semua test lolos sebelum itu. **Selalu jalankan produknya, jangan berhenti di test.**
- **Karakter BOM literal di source Go ditolak kompiler** (`invalid BOM in the middle of the file`). Untuk mencocokkan BOM, WAJIB pakai escape `"﻿"`, bukan karakter aslinya.
- **`staticcheck` menolak jalan bila dibangun dengan Go lebih lama dari yang diminta `go.mod`** (`module requires at least go1.25, but Staticcheck was built with go1.24.3`). Verifikasi lint lokal bisa mustahil; jangan klaim "lolos lint" tanpa CI benar-benar hijau.
- **Aturan audit/linter WAJIB diuji terhadap output alat itu sendiri.** Aturan `context.Background()` dan `log.Println` menyala pada constructor pool dan config loader — keduanya benar. Berteriak pada kode sendiri di run pertama membuat pengguna mengabaikan seluruh laporan; ongkosnya melebihi nilai aturannya.
- **Helper level-package di template code-gen bentrok saat entitas kedua di-generate.** Semua handler mendarat di satu package, jadi `func writeJSON` jadi redeclared. Jadikan method. Test 1-modul buta terhadap kelas ini — WAJIB ada test multi-modul.
- **`mattn/go-sqlite3` butuh cgo** dan pecah di image `CGO_ENABLED=0`. Untuk Go yang di-container-kan, pakai `modernc.org/sqlite` (murni Go).
- **`viper.Unmarshal` tidak melihat nilai yang hanya ada di environment** kecuali key-nya sudah dikenal lewat `SetDefault`/`BindEnv`. Tanpa itu `DB_USER`/`DB_PASS` diam-diam kosong di setiap deployment tanpa `.env`.
- **Cobra melewati `PersistentPostRunE` saat `RunE` mengembalikan error.** Pelepasan resource (lock, file handle) WAJIB lewat `defer` di pembungkus `Execute()`, bukan di hook Post.

## 🏛️ Arsitektur, Stack Decisions & Mastery Taxonomy

- **`go func()` / `tokio::spawn()` / `setImmediate()` BUKAN background job.** Mereka memberikan NOL durabilitas. Server crash = job hilang tanpa jejak. Durable queue (Asynq, BullMQ, Horizon, Apalis) adalah BASELINE untuk tugas apa pun yang tidak boleh hilang (email, invoice, payment), bukan fitur mewah. Background jobs = Core di SEMUA bahasa, bukan hanya di PHP.
- **Go PUNYA `reflect` package di stdlib** — dipakai berat oleh `encoding/json`, GORM, dan validator. Jangan klaim "Go tidak punya runtime reflection". Yang benar: Go punya reflection tapi komunitasnya menghindarinya demi performa. Alasan GraphQL didominasi Node.js bukan soal reflection, melainkan sejarah (lahir di Facebook JS) dan ekosistem Apollo.
- **TypeScript types TERHAPUS saat compile.** NestJS bukan "membaca tipe saat runtime". Yang jalan adalah `reflect-metadata` + `emitDecoratorMetadata` yang hanya menyimpan metadata terbatas. Generic dan union type tidak terbaca. Swagger sering tetap butuh `@ApiProperty()` manual.
- **Docker untuk Rust BUKAN trivial `FROM scratch`.** Butuh `ca-certificates` untuk TLS, musl target atau distroless untuk glibc, tzdata, `cargo-chef` untuk layer caching (tanpanya build 10-15 menit setiap push). Docker container standards = Core di Rust.
- **Node.js/PHP BISA menyentuh kernel** via N-API/native addon (Node) dan FFI/ekstensi C (PHP). Yang benar: ergonomis dan distribusinya buruk, bukan mustahil. Jangan klaim "secara fisik tidak bisa".
- **Jangan campur "sifat bahasa", "budaya ekosistem", dan "batas peran" dalam satu taksonomi.** CQRS, Kafka, chaos engineering itu Core atau Niche ditentukan oleh skala dan domain SISTEM, bukan oleh bahasa. Memaksakan taksonomi per-bahasa untuk concern yang language-agnostic menghasilkan klasifikasi yang menyesatkan.
- **Jangan gabung konsep berbeda dalam satu label domain.** `caching_strategy_cdn` mencampur caching aplikasi (Redis, cache-aside — Core) dengan CDN infra (Cloudflare — Niche). `api_versioning_gateway_routing` mencampur API versioning (Core untuk public API) dengan gateway routing (Infra). Label yang cacat menghasilkan klasifikasi yang cacat.
- **Angka tanpa sumber = karangan.** "95% pangsa pasar", "kerumitan 300%", "cold-start <10ms" — arahnya mungkin benar tapi presisinya fiktif. Kalau tidak punya data, tulis "mayoritas" atau "signifikan", jangan fabrikasi angka spesifik.
- **Structured logging (Pino/slog/tracing) adalah BASELINE, bukan kemewahan.** `console.log` di production NestJS adalah anti-pattern. OTel sudah jadi standar industri. Mengklasifikasikan telemetri sebagai Niche menghasilkan engineer yang tidak bisa debug production.
- **Contract-First & Schema Locking di Batch 1 mencegah *Integration Drift*.** Mengunci DTO/Interface/Protobuf sebelum menulis business logic memastikan lapisan Handler dan Repository tidak mengalami inkonsistensi tipe data saat multi-file batch execution.
- **Verifikasi State Nyata > Klaim Teks (Deterministic Grounding).** Nilai kecerdasan agen bukan diukur dari kecepatan mengetik kode, melainkan dari ketelitian memverifikasi mutasi state lingkungan (database rows, file diff, port, exit code terminal). Jangan pernah percaya klaim diri sendiri sebelum divalidasi oleh runtime.
- **Adversarial Self-Doubt (Skeptis terhadap Solusi Sendiri).** Bias optimisme adalah musuh terbesar AI. Agen wajib secara aktif mencari cara untuk "merusak" solusinya sendiri (boundary values, null pointer, race condition, concurrent burst) sebelum menyatakan sebuah task selesai.
- **Failure Banking (Evolusi Tanpa Regresi).** Setiap bug atau kesalahan asumsi yang pernah terjadi wajib diabadikan menjadi regression test permanen dan baris kebenaran di `LEARNED.md`. Agen yang berkembang adalah agen yang tidak pernah mengulangi jenis kegagalan yang sama dua kali.
- **Golang Architecture Scaffolding CLI vs Runtime Framework (Zero Runtime Overhead & Brownfield Adoption).** Dalam merancang alat bantu/generator untuk Golang (khususnya untuk eskalasi karir ke Principal Backend L7/L8), DILARANG KERAS melanggar filosofi *library over framework* dengan meracik *runtime framework berat* (ala Laravel/NestJS dengan reflection/magic) yang menghancurkan performa Go yang bersaing dengan C. Solusi terbaik adalah membangun **Opinionated Architecture Scaffold CLI Engine (`go-aether`)**: Generator berjalan hanya saat dev-time untuk melayari struktur *Hexagonal / Ports & Adapters* murni berbasis stdlib & router tipis (`chi`), sementara binary produksi tetap 0% overhead. Untuk menembus proyek Legacy/Brownfield berantakan tanpa *Big Bang Rewrite*, wajib terapkan 3 pilar: (1) **Interactive Anomaly Mapping** via manifest `aether.yaml` untuk menghormati dan menyelaraskan dengan folder kustom eksisting, (2) **Bring Your Own Dependency (Constructor Injection)** di mana service/repo menelan parameter pool koneksi (`*pgxpool.Pool`, `*redis.Client`, atau interface) dari `main.go` lama tanpa menduplikasikan koneksi baru, dan (3) **Vertical Slice Insular Scoping** untuk menghemat fitur baru sebagai modul self-contained terisolasi yang rapi tanpa bertabrakan dengan lautan spaghetti legacy.
- **"Sudah ada di publik" adalah alat bunuh untuk keputusan MEMBAGIKAN, BUKAN untuk keputusan MEMAKAI.** Saat user menilai ide untuk workflow pribadinya, saturasi pasar justru kabar baik (tinggal pasang, nol ongkos pembuatan). DILARANG memakai satu kriteria untuk dua jenis keputusan — tanya dulu: ini mau dibagikan, atau mau dipakai? Kriteria yang salah membunuh ide yang sebenarnya berguna.
- **Evidence Ledger bisa dipalsukan secara STRUKTUR, bukan cuma isi (Ledger Sirkular).** Ditemukan 2026-08-11: sebuah agent menjalankan skill `brainstorm` dan menghasilkan Ledger yang ketiga entrinya merujuk `LEARNED.md` milik user sendiri — Tier 0 untuk "apa yang tertulis di sana", tapi NOL bukti untuk klaim dunia luar.
